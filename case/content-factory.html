Content Factory

Автоматизированная контент-фабрика для управления персонажами, сценариями и публикациями. Принимает сырые данные через webhook, обогащает через GigaChat AI и публикует на внешние платформы.

3 воркфлоу
21 нода n8n
4 таблицы Supabase
2 AI-модели

Для чего создан

ContentFactory — стартап по автоматизации производства контента. Ручное управление персонажами, сценариями и публикациями отнимало часы, а ошибки из-за человеческого фактора приводили к срыву сроков.

Автоприём контента
Webhook принимает персонажей, сценарии и публикации от CRM и внешних систем. PII-редакция, валидация, защита от дублей.
AI-обогащение
GigaChat анализирует сырые данные и возвращает структурированный JSON: черты характера, мотивацию, арку развития, жанр, целевую аудиторию.
Автопубликация
Готовый контент уходит webhook'ом на внешние платформы. Каждая публикация логируется с полным трейсом ответа.

Архитектура

Три независимых n8n-воркфлоу, связанных через очередь в Supabase.

ШАГ 1
Webhook
POST /content-intake — приём сырых данных
ШАГ 2
Нормализация
PII-редакция, валидация, идемпотентность
ШАГ 3
Очередь
cf_inbox с уникальным ключом (source, external_id)
ШАГ 4
AI
GigaChat-2: анализ и структурирование
ШАГ 5
Quality Gate
Валидация JSON, оценка качества 0–1
ШАГ 6
Публикация
Webhook → внешняя платформа → cf_publications

Три воркфлоу

Intake Workflow
3 ноды
  • Webhook POST /content-intake
  • Нормализация + PII-редакция
  • Идемпотентный upsert в cf_inbox
Worker Workflow
9 нод
  • Schedule каждые 30 секунд
  • Claim: SELECT FOR UPDATE SKIP LOCKED
  • Guard: пустая очередь = молча стоп
  • BuildPrompt: schema по типу контента
  • OpenAI → GigaChat fallback
  • Parse + Quality Score → cf_items
Publisher Workflow
9 нод
  • Schedule каждую минуту
  • Claim: только approved без successful публикации
  • Guard: холостой прогон = стоп
  • BuildPayload: русские ключи в JSON
  • Webhook → httpbin (замена на свой URL)
  • cf_publications + cf_error_log
Что нужно для прода
Что заменить/добавить для полной рабочей версии
  • Заменить httpbin.org на URL своей CMS
  • Добавить Telegram-уведомления
  • Настроить OpenAI-ключ (сейчас GigaChat)
  • Создать дашборд для cf_items/cf_publications
  • Прикрутить авторизацию на webhook

Пример работы

Отправляем персонажа «Bob» через Intake webhook — и наблюдаем всю цепочку.

На входе (Intake)

AI-выход (Worker → cf_items)

{ "имя": "Bob", "роль": "supporting", "черты": [ "Надёжный друг", "Решительный", "Оптимистичный" ], "мотивация": "Помогать близким…", "арка": "Осознать важность…"}
