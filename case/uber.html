Бизнес-проблема

Старая версия — типовой учебный лендинг эпохи «Bootstrap + стоковые картинки». Для живого портфолио это минус: сайт выглядит на пять лет старше, а его техническая начинка не отвечает тому уровню, который я сдаю заказчикам.

  • Устаревший вид: светлый шаблонный дизайн, фоновые JPG-картинки, шрифты из 2019-го
  • Внешние зависимости: Font Awesome подключался сторонним CDN-китом — точка отказа и лишний запрос
  • Сетка на костылях: bootstrap-grid вместо нативного CSS Grid — лишний вес и меньше гибкости
  • Никакой доступности: нет prefers-reduced-motion, нет осмысленных aria-атрибутов, форма без валидации

Что изменилось

  • Дизайн: тёмная тема (#0a0a0a) с брендовым лаймовым акцентом (#EBFF01), стеклянные карточки, единый ритм секций через clamp(72px, 10vw, 140px)
  • Герой: вместо стокового фото — вращающийся каркас автомобиля, собранный процедурно в three.js (профиль кузова → экструзия → рёбра), с параллаксом от курсора
  • Контент: сохранён и причесан — 8 преимуществ карточками, две схемы работы сравнительной таблицей, четыре шага подключения, форма заявки
  • Сборка: Bootstrap и Sass убраны; чистый CSS на custom properties и ES-модули — сайт работает без сборки и без node_modules
  • Доступность: семантические секции, aria-атрибуты, focus-стили, prefers-reduced-motion, форма с валидацией и live-статусом

Как устроен 3D-каркас

В герое — настоящая модель спорткара (CC-BY 4.0, автор Neill Bogie), а не примитивы из кода. Но подана она в фирменной «экзоскелетной» стилистике:

  • Модель: оригинальный CC-BY GLB-набор (17 машин, 1,6 МБ) — в рантайме берётся узел car_sports_striped (getObjectByName), остальное отбрасывается до рендера; свой скрипт-экстрактор одной машины был написан, но давал битую геометрию колёс — от него отказались после автоматической проверки рендера
  • Каркас: каждый меш модели получает тёмный корпус (скрытые задние рёбра не «просвечивают») + EdgesGeometry с лаймовыми рёбрами поверх — узнаваемый цифровой прототип
  • Нормализация: Box3 — масштаб до длины 4,4 м, центр в начале координат, колёса стоят ровно на сетке-полу
  • Сцена: перспективная сетка, туман для глубины, медленное авто-вращение, параллакс от курсора
  • Двухступенчатый fallback: не загрузилась модель → процедурная машина из кода; нет WebGL / включён prefers-reduced-motion → статичный SVG-чертёж

Архитектура

index.html — разметка + import map ("three" → vendor/three.module.js) ↓ css/style.css — токены (:root), mobile-first, clamp-ритм, reduced-motion ↓ js/app.js — ES-модуль: меню, reveal-анимации, валидация формы ↓ dynamic import (ошибка = SVG-fallback, остальной JS живёт) js/car.js — three.js: сцена, каркасная подача модели, параллакс, пауза рендера ↓ dynamic import('./loaders/GLTFLoader.js') js/loaders/GLTFLoader.js + js/utils/BufferGeometryUtils.js — вендорные загрузчики r160 ↓ car.glb — CC-BY набор машин (1,6 МБ), в рантайме выбирается спорткар vendor/three.module.js — three.js r160, лежит в репозитории (без CDN)

Модель и загрузчик подгружаются асинхронно и не блокируют остальной JS: меню, форма и анимации работают, даже если 3D не инициализировалось. Рендер ставится на паузу, когда герой уходит за экран (IntersectionObserver) или вкладка скрыта; devicePixelRatio ограничен 2.

  • Автопроверка: headless Edge по CDP (SwiftShader WebGL) — скриншот героя и консоль без ошибок; так же был пойман битый экстракт модели
